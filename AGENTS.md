# Neon development
- HUD entries and color popup expansion controls use `+` when collapsed and `−` when expanded, with compact labels/values and usable inline sliders, falling back to a full-width bar below on narrow displays and no Reset button. Keybinds appear only right-aligned in module buttons in brackets, such as `[M5]`, never inside expanded settings. Module and Settings grid buttons have no `+`/`−` marks. On keybind hover, replace the key inside the same brackets with the mode ([Hold], [Toggle], [Reverse hold]); restore the key on leave. No floating mode tooltip or persistent T/H/RH indicators. Freelook expands a Distance setting (1–16 blocks, default 4); keep its bind only in the header. Motion blur defaults to 10% strength; preserve saved custom values.
- The menu supports the saved primary binding (Insert in Vanilla) plus a separate Right Shift alternate binding for opening and closing. Keep key capture and focused text input ahead of menu shortcuts, and discard shortcut presses made in chat.
- Target Minecraft 26.2, Java 25, and unobfuscated Fabric Loom.
- Run an actual Gradle build after each completed code/configuration change set.
- The build installs only a successfully checked runnable JAR into PrismLauncher Vanilla.
- Keep running Minecraft instances open. Never install a stale JAR after a failed build.
- Keep verification clients silent: suppress Minecraft and Neon audio in the test harness while retaining sound-trigger assertions. Never play test sounds through the user's speakers.
- Preserve Unity's separate checkout and installed artifacts.
- Better chat adapts Unity's duplicate counts, animation and name highlighting in Visuals. Preserve original chat history/signatures and links. Emit one message or mention ping only on accepted new player/server chat, with independent ping volume; chat reflows, local notices and action bars stay silent.
- Never show scrollbars in Neon; retain smooth wheel scrolling and immediate keyboard focus reveal. Keep Combat, Visuals, and Settings as the three categories. HUD editor is a direct sidebar action beneath Settings, visible from every category. Colors open the user-approved compact floating panel beside the menu, top-aligned, with live HSV/opacity, original/current previews, hex editing, and Unity's Copy/Paste mechanics. Use original soft console-style cues for hover/focus, navigation/back, confirmations and enable/disable actions. Emit one cue per input; keep continuous scrolling, dragging, resizing, color adjustments, typing and unchanged/rejected actions silent. Test clients must remain fully muted. New/reset armor sits bottom-aligned left of the offhand slot/hotbar; preserve existing custom placements.
- The sidebar HUD editor action beneath Settings opens the editor directly and returns to the prior category, drawer and scroll positions. All armor/totem configuration lives in Unity-derived expandable rows there, with inline numeric editing and direct canvas placement; no intermediate cards, coordinate forms, or position presets. Appearance colors apply live in one floating popup without replacing the menu or moving its rows; dismiss with outside click or Escape and keep the applied color. Fit the popup within the display at every menu size. Inspect actual module/settings pages at default and minimum sizes before declaring UI work complete.
- HUD canvas elements have no selection outlines, drawn resize handles, or floating labels. Keep invisible-corner resizing and direct dragging. Render and hit-test only enabled HUD elements, including editor previews; keep disabled modules available in the column. Do not snap to hidden widgets. The HUD column uses a quiet static border.
- Follow `docs/design-language.md` and `docs/neon-design-reference.html` for every client UI change. The latest user-approved module layout supersedes option B: compact, equal-width outlined buttons in a spaced wrapping grid. Left click toggles; right click opens a smooth right-hand settings drawer while keeping the grid visible. Bracketed binds sit at the right edge of each module button; left click assigns and right click cycles Toggle, Hold, Reverse hold, shown only as the full mode name on bind hover. No bind-mode controls inside settings. Boolean module settings keep the cyan rectangular switch; do not replace the compact module-button enabled indicator with a switch. The outer colored outline expands around both panes as one mesh. Preserve the traveling glow's physical position along its edge during expansion/reversal; never rebase it around a changing center. Use a two-display-pixel hover lift with a clearly visible, smoothly fading cyan-to-violet Gaussian bloom, a brighter border and matching surface tint over 220 ms. Keep adequate grid padding so the hover bloom is not clipped. Module, Settings and ordinary action buttons use light-glass fills: 18% at rest and 28% on hover or selection, multiplied by saved Cards alpha and menu opacity. Sidebar rows are clear at rest with faint hover/selection tint. Preserve functional slider, switch and swatch colors. Settings sections use the same outlined button grid and right-hand drawer; either mouse button opens a section, without module toggles or binds. HUD retains its expandable rows. Use an independent display-pixel scale so Minecraft's GUI scale never enlarges the menu. Use the 132.25% interface scale, with a compact 582×370 display-pixel default window and native-resolution Inter text (16px body, 15px secondary, 19px headings), sharp dark panels, a thin cyan/violet animated outline with localized bloom traveling with the bright colored highlight (no full perimeter halo), and restrained active-control glow. Keep Combat and Visuals at the top of the sidebar with small line icons; stack centered Settings and HUD editor actions at the sidebar bottom, with no Visuals footer; Appearance and Profiles belong inside Settings without a keybind list. Move by the header and resize through invisible corners. No Overview, decorative copy, X, Undo, or Done buttons. Keep Escape and Ctrl+Z working without a footer. Match Unity's compact draggable column for the HUD editor, with collapsed widget settings and an unobstructed canvas; no full-width toolbar or bottom hint. Keep HUD widgets limited to armor, totems, and the user-requested Unity FPS element. No Advanced folds in modules; expose a short set of useful controls directly. Use native display-pixel control borders, independent HUD scale and pixel snap sensitivity. Keep the totem count attached to the real offhand slot as explicitly requested; armor/floating widget sizes use Neon scale. UI audio uses Neon volume independently of Minecraft audio. Colors owns Opacity; Appearance has direct UI sounds and Effects controls.
