# Neon development
- Target Minecraft 26.2, Java 25, and unobfuscated Fabric Loom.
- Run an actual Gradle build after each completed code/configuration change set.
- The build installs only a successfully checked runnable JAR into PrismLauncher Vanilla.
- Keep running Minecraft instances open. Never install a stale JAR after a failed build.
- Preserve Unity's separate checkout and installed artifacts.
- Never show scrollbars in Neon; retain smooth wheel scrolling and immediate keyboard focus reveal. Use only Combat, Visuals, HUD, and Settings. Match Unity's inline color fold, live HSV/opacity, original/current previews, and Copy/Paste mechanics. Play the quiet original Neon sound only when enabling a module; color editing, navigation, settings, and disabling modules stay silent. New/reset armor sits bottom-aligned left of the offhand slot/hotbar; preserve existing custom placements.
- HUD opens the editor directly. All armor/totem configuration lives in Unity-derived expandable rows there, with inline numeric editing and direct canvas placement; no intermediate cards, coordinate forms, or position presets. Appearance colors expand inline and apply live; never replace the menu with a color dialog. Inspect actual module/settings pages at default and minimum sizes before declaring UI work complete.
- HUD canvas elements have no selection outlines, drawn resize handles, or floating labels. Keep invisible-corner resizing and direct dragging. Render and hit-test only enabled HUD elements, including editor previews; keep disabled modules available in the column. Do not snap to hidden widgets. The HUD column uses a quiet static border.
- Follow `docs/design-language.md` and `docs/neon-design-reference.html` for every client UI change. The user approved option B: flat expandable module rows, separate square enable targets, name-adjacent binds, and inline indented settings. Keep the module list visible, with thin separators instead of card boxes. Use an independent display-pixel scale so Minecraft's GUI scale never enlarges the menu. Use the 132.25% interface scale, with a compact 582×370 display-pixel default window and native-resolution Inter text (16px body, 15px secondary, 19px headings), sharp dark panels, a thin cyan/violet animated outline with localized bloom traveling with the bright colored highlight (no full perimeter halo), and restrained active-control glow. Keep Combat, Visuals, HUD, and Settings in the sidebar with small line icons; Appearance and Profiles belong inside Settings without a keybind list. Move by the header and resize through invisible corners. No Overview, decorative copy, X, Undo, or Done buttons. Keep Escape and Ctrl+Z working without a footer. Match Unity's compact draggable column for the HUD editor, with collapsed widget settings and an unobstructed canvas; no full-width toolbar or bottom hint. Keep HUD widgets limited to armor and totems. No Advanced folds in modules; expose a short set of useful controls directly. Use native display-pixel control borders, independent HUD scale and pixel snap sensitivity. Keep the totem count attached to the real offhand slot as explicitly requested; armor/floating widget sizes use Neon scale. Module-enable audio uses Neon volume independently of Minecraft audio. Appearance has direct Opacity, Module sound and Effects controls.
