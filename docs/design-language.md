# Neon design language

The user approved option B, **Expandable rows**, on 9 November 2026, then requested localized bloom traveling with the colored outline highlight, simpler direct settings, independent HUD scale/audio, and the quiet gray selection from their latest sidebar reference. The approved concept is [saved here](images/neon-expandable-rows-reference.png); `neon-design-reference.html` records the current compact layout. This replaces the earlier card-grid/focused-page navigation. Compare actual physical display pixels at multiple Minecraft GUI scales; matching logical coordinates alone is not visual parity.

- The user requested two successive 15% increases after the density correction and prioritized clean text over tiny controls. Apply a fixed 132.25% interface scale independent of Minecraft's GUI scale. The default is now approximately 582×370 display pixels, reduced on smaller displays, with a 423×278 readable minimum where space permits. Minecraft GUI scales 1, 2, and 3 must produce the same control dimensions and font size. Legacy oversized window placements return to the compact default once; saved compact placements receive only the density increases they have not yet received. Subsequent placements persist normally.
- Move by dragging the header, including the brand. Resize by pulling any corner. Do not draw grips, resize icons, or instructional copy. Keep the window reachable after viewport changes; save its placement independently of settings profiles.
- Sidebar: Combat, Visuals, HUD, Settings, each with a small native-resolution line icon. No Overview. Combat and Visuals contain flat vertical module rows; HUD opens the live editor directly. The bind sits immediately after the name: `Autoclicker [M5]`. Use complete compact key names such as `[DEL]`, with measured widths rather than clipping or ellipses. Show only real bindings; the concept's example keys are illustrative.
- Each module has a separately clickable square enable target. Clicking its name or chevron expands settings directly below; clicking again collapses. Keep the category title and sibling module rows visible. Indent settings to align with the module name, use a quiet cyan selected fill and faint separators, and never draw a card border or duplicate Enabled row around the expansion. No Advanced folds: Zoom exposes Activation, Magnification, Transition and Scroll zoom; Motion blur exposes Strength and Blur the UI; Autoclicker exposes its useful click controls and Entities only. Keep immediate input and 150 ms expansion feedback. The only Freelook setting is its bind; keep it available when expanded.
- Settings contains Appearance and Profiles. Bind capture stays on each module; the menu key uses Minecraft's key bindings and defaults to P. Do not put a bind list in Settings.
- Appearance includes Background, Outline, Accent, Text, and optional Cards, Secondary outline, Muted text. Port Unity's inline picker mechanics: left or right click anywhere on a color row toggles its fold; opening another color replaces the fold. Use a square saturation/brightness surface, horizontal hue and opacity strips, original/current swatches, and Copy/Paste. Apply changes during dragging; closing or Escape keeps the applied color. Copy uses #RRGGBBAA; paste accepts Unity's hex, RGB(A), HSB, and named-color formats. No separate window or Apply/Cancel buttons. Keep a whole gesture as one Undo step. At minimum size, scrolling reaches the final picker actions. Profiles include appearance and alpha; window placement and key bindings remain global.
- Inter typography at native display resolution: 16-pixel body, 15-pixel secondary, and 19-pixel headings/brand. Shape complete text runs with kerning, render at 4× resolution, and area-resolve the coverage before caching. Composite one resolved texel per display pixel, with pixel-aligned origins and no second resampling. Preserve smooth edge alpha and white transparent padding to avoid dark fringes. Editable fields use the same native-resolution text renderer and measured cursor/selection positions while retaining vanilla keyboard editing and IME composition state. No Minecraft font on custom controls. Native game items use Neon's physical HUD geometry in both gameplay and the editor; the attached offhand count retains the actual offhand slot geometry.
- Base geometry before the fixed 132.25% scale: 440×280 window, 96-unit sidebar (to fit icons and complete labels), 37-unit header, 12-unit content inset, 26-unit module rows, 26-unit setting indentation, and 23-unit category targets on a 25-unit pitch. This produces a 127-pixel sidebar and roughly 34-pixel module rows. Use one column with no card boxes. Keep binds content-sized. No X, Undo, or Done buttons and no reserved footer strip. Escape collapses/goes back/closes; Ctrl+Z retains Undo.
- Default palette: background `#0e131b`, cards `#121923`, text `#e3eaf1`, muted `#83909f`, structure `#27313c`, accent `#84dce6`, outline `#73c8d3`, secondary outline `#9985cc`. Sidebar is the background mixed with 17% black.
- One-display-pixel animated cyan/violet outline with a bright traveling highlight and localized eight-display-pixel bloom around that moving highlight, including continuous corner joins. The rest of the border stays thin with no full-window halo. Use a single ordered, pixel-aligned border mesh so fractional UI scales cannot create seams. No segmented trails or stepped rectangle halos. Keep active-control glow restrained. All control strokes use native display pixels. Animate hover/switch states without rounding their geometry.
- Keep keyboard navigation, narration, exact-value input, cancellation, Undo, profiles, and error handling functional. The live HUD editor remains limited to armor and totems.
- No visible scrollbars or draggable scrollbar hitboxes anywhere in Neon. Wheel motion is bounded and smooth; keyboard focus reveals controls immediately. Keep the four-category sidebar compact, with a clear selected fill inspired by the user's Prestige reference; do not copy its extra categories or rounded corners.
- Use 100 ms hover transitions, 120 ms menu opening fades, and 150 ms folds. Input and settings apply immediately. Numeric edits stay inline: Enter commits, Escape cancels, valid outside clicks commit, invalid drafts stay marked. Preserve focused drafts and widget state through resizing and settings changes.
- Appearance directly contains its seven colors, Opacity (40–100%, default 94%), Module sound (0–100%, default 40%), and Effects: Adaptive / Full (default Adaptive). Only menu background blur and decorative control glow may adapt. Neon has its own fixed backdrop blur strength without changing the saved Minecraft preference. Keep the dark backdrop, native text, animated perimeter and its traveling bloom, HUD items, and gameplay motion blur at full quality. Only enabling a module plays a quiet original Neon sound, through Neon's own asynchronous audio line and volume independent of Minecraft sound settings. Color editing, navigation, other settings, and disabling modules stay silent; never use vanilla menu clicks. Profiles persist opacity, sound volume, HUD scale and snap sensitivity.
- Detail controls use 27-unit rows and an eight-unit gutter before the scroll edge. Keep switches, complete bind labels, segmented choices, glow, and focus feedback inside the visible column. Wrap choices on very narrow layouts. Mouse clicks must not leave large focus boxes around sliders; keyboard focus remains visible. Back navigation uses the same antialiased font renderer as text.
- HUD editor: follow Unity's single draggable column, approximately 249 display pixels wide with 29-pixel header/rows, 118 pixels tall when collapsed (base geometry 188×89, 22-unit rows). Start with collapsed Armor, Totems, and General entries. Left click toggles a widget; right click opens its settings, including right click directly on the canvas widget. Tab or H hides the controls. Hide the whole column during move/resize gestures, then restore it on release. Keep the world sharp and undimmed, suppress chat while editing, and show guides only during a gesture. No full-width toolbar, footer buttons, permanent crosshair guides, bottom help banner, or oversized selection handles. Canvas coordinates and item sizes must match actual gameplay; the global HUD scale controls item size separately from editor typography.

HUD opens directly from the sidebar, with every armor and totem option in the editor's expandable column. Port Unity's row model, slider motion, and corner-resize math with Neon-specific config/rendering adapters. Armor controls cover scale, orientation, frames, order, spacing, warnings, threshold, and damage preview; totems cover scale and offhand/floating mode. Numeric values edit in their rows. Placement is direct: no X/Y forms, position preset grids, or extra Edit HUD launch buttons. Dragging an offhand totem switches it to free placement; Ctrl+Z restores the whole change. General holds HUD scale (0.5–2×), Guides, Snap, and Snap sensitivity (1–24 display pixels). Armor and floating totems use a fixed two-display-pixel item density multiplied by HUD scale and their individual scale, independent of Minecraft GUI scale. Editor and gameplay share physical geometry. Arrow keys move one display pixel (Shift: ten). The user explicitly chose to keep the totem count attached to the real offhand slot: attached totems follow that slot's size and position; HUD scale does not detach or resize it. New/reset armor follows the hotbar's position with its own independent item size.

New/reset armor defaults to bottom alignment immediately left of the offhand slot/hotbar, matching the user's screenshot. Preserve existing custom positions when loading configurations or profiles.

The latest HUD correction removes canvas selection outlines, visible resize handles, and floating name/coordinate labels, including while dragging. Keep direct dragging and invisible-corner resizing. Only enabled HUD elements are rendered or receive canvas input; disabled elements remain available as rows in the configuration column. Do not force disabled armor/totems into preview mode or snap to hidden widgets. The column has a quiet static border; the traveling bloom belongs to the menu outline. Optional guides remain under General.

The reference is a proposed UI, not evidence of runtime correctness. Validate rendering, interactions, persistence, and viewport changes on the packaged production JAR. Inspect actual detail pages, expanded options, all inline color pickers, and the HUD editor at default and minimum sizes, including the last scrolled row. Preserve Unity's separate checkout and artifacts.
